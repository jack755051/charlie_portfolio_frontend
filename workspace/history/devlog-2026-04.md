## 2026-04-19 ｜ 修復 home-terminal.vue i18n 片語型別錯誤

### 1. 事件摘要
- **現象**：執行 `npm run dev` 後首頁 SSR 階段回傳 **500**，錯誤訊息 `TypeError: currentPhrase.substring is not a function`。
- **觸發來源**：`components/features/home-terminal.vue` 打字機效果模組。

### 2. 根因分析（02 Tech Lead）
- 專案啟用 `@nuxtjs/i18n`（`nuxt.config.ts:15-28`），底層 `@intlify/unplugin-vue-i18n` 在 build 期會把 `i18n/locales/*.json` 的每個葉節點字串**預編譯為 message compiler function**。
- 原實作於 `home-terminal.vue` 直接 `import zhLocale from '~/i18n/locales/zh.json'`，繞過 i18n runtime，取到的 `home.roles[0]` 為 function 而非字串。
- Function 物件無 `String.prototype.substring`，故於 `typeEffect()` 拋錯。

### 3. 技術決策（ADR）
- **選型**：採用 **`useI18n()` runtime API**（`tm()` 取訊息樹 + `rt()` 解析為字串）。
- **否決方案**：
  - 直接 type cast 成 string：僅掩蓋型別錯誤，runtime 仍為 function。
  - 將 roles 移出 i18n 以常數管理：違背既有 i18n SSOT 策略。
  - 關閉 `@nuxtjs/i18n` compilation：全站效能受損，成本不對等。
- **對齊規範**：`docs/agent-skills/04-frontend-agent.md` §3.3（服務層資料清洗）— 不應讓 UI 元件直接吃 raw i18n 資源。

### 4. 變更清單

| --- | --- | --- |

## 2026-04-19 ｜ Hero 區塊 UI/UX 全面升級（Phase 1~3 一次到位）

### 1. 背景與動機
- UI 稽核發現：手機完全看不到 Terminal 卡片（`hidden md:flex`）、僅單一 md 斷點、無 dark mode、標題平淡無視覺焦點、背景單調。
- 需對齊 2026 主流工程師作品集常見元素：gradient mesh 背景、gradient text、display/mono 字體、dark mode、micro-interaction。

### 2. 技術決策（ADR）
- **字體**：採用 **Sora**（display）+ **JetBrains Mono**（code），透過 Google Fonts 載入並以 `preconnect` 降低首載延遲；於 `tailwind.config.js` 擴充 `fontFamily.display` / `fontFamily.mono`。
- **Dark Mode**：採 Tailwind 預設 `media` 策略，跟隨作業系統偏好，**無需 JS 切換**、**無需 localStorage**，最低成本導入。
- **背景裝飾**：三顆 `blur-3xl` 模糊色塊 + `radial-gradient` dot grid pattern，以 `pointer-events-none` 防干擾點擊。
- **動效**：
  - `animate-float-slow`（blob 緩慢浮動，6s）
  - `animate-blink`（caret 閃爍，1.1s steps）
  - `animate-fade-in-up`（標籤淡入）
  - 全數支援 `prefers-reduced-motion` 關閉。
- **RWD 重構**：移除 `hidden md:flex`，改以 `grid-cols-1 md:grid-cols-2` + `order-*` 於手機將 Terminal 置於文字上方；補齊 `sm / md / lg` 斷點對字級、padding、gap 做細調。
- **Gradient Text**：標題套 `bg-gradient-to-r from-orange-500 via-rose-500 to-fuchsia-500 bg-clip-text text-transparent` + `drop-shadow` 輕發光。
- **CTA 按鈕**：`flex-wrap` 防手機擠壓；主按鈕加 `hover:-translate-y-0.5` + shadow glow；次按鈕 dark mode 補色。
- **Terminal 強化**：加入行號欄位（`select-none`）、游標 blink、hover 時 `ring-orange-500/40` 發光。

## 2026-04-19 ｜ Workflow 整併 + 主線切換（dev 成為 default branch）

### 1. 背景
- 使用者在 Actions 頁發現只有 `Deploy to GitHub Pages` + `pages-build-deployment` 兩個 workflow，`Sync LeetCode Profile` 不見。
- 診斷：`sync-leetcode.yml` 只存在於 `feat/*` 與 `chore/*` 分支，**從未進 `master` 或 `dev`** → GitHub 無法識別 → scheduled cron 永遠不會執行。
- 另外 `dev/deploy.yml` 使用 `publish_dir: ./dist`（Nuxt 2 / Vue CLI 慣例），但 Nuxt 3 輸出為 `.output/public` → 部署其實靠舊快取運氣。
- `origin/master` 停在 `2025-07-12` 近 10 個月；`origin/dev` 才是實際主線 → 正名為 default branch。

### 2. 決議（ADR）
- **方案 B**：把 `chore/tone-down-copy`（分支鏈頂點，已涵蓋所有 feat/* UI + 文案 + Token 改動）FF merge 進 `dev`，一次帶入所有改動。
- **方案 2（分支策略）**：將 GitHub default branch 由 `master` 改為 `dev`，正式宣告 `dev` 為主線。
  - 原因：`master` 僅 placeholder；`dev` 累積實際歷史；workflow 已對齊 `dev`。
  - 影響：GitHub scheduled workflow 會從 default branch 讀取定義 → 改 default 後 cron 才會識別 `sync-leetcode.yml`。
- **Workflow 整併**：刪除 `deploy.yml`；擴充 `sync-leetcode.yml`，合併三項職責：
  1. `schedule`：每日 02:17 Asia/Taipei 同步 LeetCode 資料
  2. `workflow_dispatch`：手動觸發
  3. `push: [dev]`：push 到 dev 自動重新部署

### 3. 關鍵技術設計（避免循環與衝突）
| 機制 | 設計 |
| --- | --- |
| 避免循環 sync | `if: github.event_name != 'push'` 限制 sync + commit 僅於 cron/manual 執行 |
| 避免併發衝突 | `concurrency: sync-leetcode-deploy` 群組避免雙部署 |
| 對應 peer dep 問題 | `npm ci --legacy-peer-deps` 處理 ESLint v8/v9 衝突 |
| 明確 checkout | `ref: dev` 顯式指定，切換 default branch 前後都正確 |

### 4. 變更清單

### 5. 合併與部署步驟（人工操作序列）
1. Commit + push 本分支 `chore/tone-down-copy`（workflow 整併）
2. `git checkout dev` → `git merge chore/tone-down-copy --ff-only` → `git push`

## 2026-04-19 ｜ Scroll UX 微調（snap-mandatory → snap-proximity）+ Tag v0.0.2

### 1. 問題
使用者回報兩個感受：
1. 點左側 CAnchor 導引 → smooth 動畫結尾出現「硬 snap」
2. 滑鼠滾輪捲動時「無法停在 section 中間」

### 2. 根因（03 UI 診斷）
- 3 個 scroll 容器採 `snap-y snap-mandatory` + `scroll-smooth`
- `snap-mandatory` 強制對齊每個 `snap-start` 邊界
- 與 `scrollIntoView({ behavior: 'smooth' })` 的平滑動畫互搶，動畫尾端被強制校正
- 滾輪 tick 被強制吸附，無法在 section 內部自由捲動閱讀超長內容

### 3. 決策（ADR）
- **採 Strategy A（snap-proximity）**：保留 snap 的「輕吸引」語義，但放棄強制
- 否決 B（全自由滾動，失去 portfolio 型分段感）
- 否決 C（Lenis.js，bundle 成本大於需求）

### 4. 變更清單
| 檔案 | 變更 |
| --- | --- |
| `components/features/home-terminal.vue` | `snap-mandatory` → `snap-proximity` |
| `pages/about/index.vue` | 同上 |
| `pages/portfolio/index.vue` | 同上 |
| `components/base/anchor.vue` | `document.querySelector('.snap-y.snap-mandatory')` → `.snap-y`（2 處；解除 snap 強度耦合）|

### 5. 品質與部署
- ESLint：0 error
- Push 至 `dev` → 自動觸發 `Sync LeetCode & Deploy` workflow → gh-pages 重建

## 2026-04-19（晚）｜ 分支清理 + Header Sticky / Footer 解凍

### 2. Footer 不該 freeze 的根因（03 UI 診斷）

| `footer.vue` 移除 `mt-auto`、加 `border-t border-border/40` | footer 回歸正常 flow，捲到底才露出 |
